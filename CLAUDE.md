# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Noctara is a native SoundCloud desktop client written in C++23 with Qt 6 Quick. It is built with xmake, clang and mold. Work proceeds in vertical "slices" (a)…(j), listed in `docs/plan.md` together with the verified toolchain versions and the design decisions taken so far. The full product spec drives everything: settings come from one schema, every string is translated (en/ru), everything has a software-rendering fallback, and both themes are supported.

## Build, test, run

```sh
xmake f -m debug --qt=/usr/lib/qt6 --werror=y   # --qt is required: otherwise xmake picks a co-installed Qt 5
xmake build -a                                  # app + noctara-tests + noctara-schema-doc
./build/linux/x86_64/debug/noctara-tests        # doctest; single test: -tc="name*", suite: -ts=settings.toml, -ts="net.*"
./build/linux/x86_64/release/noctara-tests --no-skip -tc="transport spike*"   # skipped by default: measurements
./build/linux/x86_64/debug/noctara-tests --no-skip -tc="real network*"        # skipped by default: real internet
./build/linux/x86_64/release/noctara-tests --no-skip -tc="*benchmark"        # QML/model timings: settings slider step, button crossfade, row reuse, tooltip hosts
xmake drm-helper                                # castlabs Electron + hls.js (pinned, verified) → build/drm-helper
xmake build noctara-bench && ./build/linux/x86_64/release/noctara-bench [filter]   # hot-path timings (release mode)
xmake f --trace=y                               # compile in core/Trace.hpp scopes; Chrome trace JSON at exit ($NOCTARA_TRACE_FILE)
xmake smoke                                     # every page: {software, GPU} x {dark, light} x {en, ru} + blur x surface styles; fails on any warning
xmake lint                                      # clang-tidy over src/, tools/, bench/ (not tests/); any finding fails it; needs compile_commands.json
xmake format [--check]                          # clang-format
xmake i18n-update && xmake i18n-check           # lupdate; CI gate: ru translation complete and .ts in sync
xmake docs-config [--check]                     # regenerate/verify docs/configuration.md from the settings schema
xmake f -m tsan && xmake build noctara-tests && xmake test-tsan
xmake pgo                                       # instrumented release build → --pgo-scenario run → llvm-profdata merge → optimised rebuild
xmake package                                   # release tarball with desktop file and icons in build/dist (release config first)
./install.sh [--prefix DIR|--system] [--no-deps]   # user install from this tree; get.sh is the curl | bash entry point, uninstall.sh removes
```

Modes: `debug` runs ASan+UBSan, `release` uses -O3, ThinLTO, hardening and -Werror, and `tsan` is separate. The release check before a commit is `xmake f -m release && xmake build -a`. Every build copies the binary to `build/noctara`. Config options (`xmake/options.lua`): `--werror`, `--release_werror` (release forces `-Werror` unless this is `n`; the installer turns it off because users' compilers warn differently), `--march`, `--lto`, `--sanitizers`, `--pgo=generate|use`, `--trace`.

The installer scripts (`get.sh`, `install.sh`, `uninstall.sh`) build release with `--march=native --release_werror=n` and record what they copied in `<prefix>/lib/noctara/manifest`; uninstall removes only those files. Package names per package manager live in `install.sh`'s `packages()`. Test them with `NOCTARA_REPO_URL=<local path> NOCTARA_REF=<branch> NOCTARA_SOURCE_DIR=<tmp>`, isolated XDG directories and a scratch `--prefix`; questions read `/dev/tty`, so drive them through `script -qec`. Stub `secret-tool`, `pgrep` and `pkill` on `PATH` in purge tests: `--purge` clears the real keyring entries and closes a running Noctara.

A fresh machine needs every package of the README's Arch line (CI installs the same list): without `qt6-tools` (lrelease, lupdate) or `qt6-shadertools` (qsb) configuring stops with "… not found in the Qt installation", and the error names the package.

CI (`.github/workflows/ci.yml`) runs on Arch as root, hence `--root` on every xmake call (tasks that run nested xmake add it themselves when `os.isroot()`). The matrix is debug and release: build, tests, smoke, format/i18n/docs, lint. A separate job runs TSan. A new pkg-config dependency must also go into its `pacman` lines (`pkgconf` itself is needed too).

Before committing, run all of these: `xmake format` then `--check`, a `--werror=y` build, the unit tests, `xmake smoke`, `xmake i18n-check`, `xmake docs-config --check` and `xmake lint` (0 findings). Commits are made per slice; review fixes go in separate commits.

### Running the app during development

Run with isolated XDG directories so the real `~/.config/noctara`, `~/.cache/noctara` and `~/.local/state/noctara` are not touched:

```sh
XDG_CONFIG_HOME=/tmp/x/c XDG_CACHE_HOME=/tmp/x/ca XDG_STATE_HOME=/tmp/x/s QT_QPA_PLATFORM=offscreen \
  build/noctara --page settings/appearance --theme=dark --lang=ru --screenshot out.png
```

- **Hidden dev flags:** `--page <id>[/<settings category>]`, `--navigate <page>[,<page>…]|appearance-panel|queue-panel|full-player|cheat-sheet|track:<id>` (switches after startup, every 500 ms; repeat a step to delay the screenshot; `track:<id>` opens a track page and needs internet), `--screenshot <file>` (grabs the window after 1.5 s and quits), `--smoke-test`, `--artwork <image>` (stands in for the current track's artwork: accent and cover backdrop), `--play <soundcloud link>` (resolves and plays it; needs internet). The `--play` + `--screenshot` combination plays real audio through the default device.
- **The offscreen QPA does not draw ShaderEffects**, even on the GPU path. To check glass, shadows or Liquid Glass visually, drop `QT_QPA_PLATFORM=offscreen` (a window appears briefly), or run `NOCTARA_SMOKE_PLATFORM=wayland xmake smoke`.
- `QT_LOGGING_RULES="noctara.gfx.debug=true"` prints per-second frame stats (fps, GPU time from QRhi timestamps).
- **Public flags:** `--print-config`, `--reset-config`, `--safe-mode`, `--gpu=auto|on|off`, `--set key=value`.

If a run crashes **or is killed** (e.g. by `timeout`) before its first frame, the crash sentinel makes the *next* launch start in Safe Mode (software rendering, Solid glass). That is expected behaviour, not a new bug: delete `$XDG_STATE_HOME/noctara/graphics-init.sentinel` between scripted runs. On Wayland a test window may never be exposed (e.g. on another workspace); its animations then do not advance and screenshots show a half-faded UI, which is not an app bug either. Logic that does not need shaders is checked most reliably offscreen.

## Architecture

There is one static library per module under `src/`, declared through `noctara_module()` in `xmake.lua`, and dependencies point downward only:
`core` ← `settings` ← `i18n` / `theme` / `gfx` / `net` ← `cache` ← `api` ← `models` ← `media` ← `drm` ← `ui` ← `app` (the composition root, `src/app/main.cpp`); `auth` depends on `core` only. The QML in `src/qml/` is presentation only. All logic lives in C++ objects registered as QML singletons in `main.cpp`: `Theme`, `Format`, `SettingsUi`, `App`, `Graphics`, `Language`, `Performance`, `Artwork`, `Network`, `Storage`, `Catalog`, `Account`, `Player`, `Themes`, `Shortcuts`, `Layout`, `Tray`. The app object is a `QApplication` (the tray menu is a `QMenu`); tests use `QGuiApplication`. Types are registered manually, not through qmltyperegistrar, and QML is loaded from generated `.qrc` files.

- **Settings are the single source of truth.** `src/settings/BuiltinSchema.cpp` declares every setting: key, type, default, range or enum, category, translatable label and description, restart flag, advanced flag, `visibleWhen`, and CLI alias. Everything else derives from it:
  - the generated settings UI (`ui/SettingsModel` drives `qml/settings/SettingsRow.qml`, which has no hand-written rows)
  - TOML parsing and validation
  - environment overrides (`NOCTARA_<KEY>`) and CLI overrides
  - `docs/configuration.md`

  Adding a setting means adding one schema entry and a key constant in `settings/Keys.hpp`, then running `i18n-update`, adding the Russian translation and running `docs-config`. Renaming a key, changing its type, or changing the meaning/scale of a stored value needs a migration in `settings/Migrations.cpp` and a bump of `Schema::kConfigVersion`. Files without `config_version` are treated as v0 and run through *every* migration, so tests that write config files must include the current version. Use `ConfigOnly` for settings edited by a dedicated control rather than a generated row.
- **`SettingsStore` layers**, lowest precedence first: Default < System < User < Env < CLI. UI edits go to the User layer through `setUserValue` and are refused when env or CLI pins the key. `ConfigFile` persists that layer. It saves debounced and atomically on its own I/O thread, regenerates a fully documented TOML file while keeping unknown keys, and hot-reloads external edits: a syntax error keeps all old values, an invalid key keeps its previous value.
- **Theme.** `theme/Palette.cpp` is a pure function: one OKLCH seed plus the scheme gives every color role, and WCAG contrast is *enforced* against the worst-case glass background. `theme/Tokens.hpp` defines the Q_GADGET token groups exposed as `Theme.colors/space/radius/font/motion/glass`. Color roles are declared once in the `NOCTARA_PALETTE_ROLES` X-macro, but each role also needs a `Q_PROPERTY` line in `ThemeColors` because moc does not expand macros. Icons bind to `Theme.targetColors`, not `Theme.colors`, so they are not re-rasterized during crossfades. Motion easing must never overshoot: use `Theme.motion.easingStandard/easingEmphasized` and never `OutBack`.
- **Graphics bootstrap** (`gfx/`). `decide()` in `GraphicsPolicy.cpp` is pure and tested with mocked probes. `bootstrapGraphics` runs after `QGuiApplication` is created and before any window: it arms the crash sentinel, runs a cached QRhi probe whose cache is keyed by a driver fingerprint (and the GPU preference), checks the data-driven blocklist (`resources/data/gpu-blocklist.json`), then calls `QQuickWindow::setGraphicsApi`. Auto tries Vulkan first, then OpenGL; a CPU-only Vulkan (lavapipe) does not stop the search. The Vulkan probe pins the preferred physical device via `QT_VK_PHYSICAL_DEVICE_INDEX`. `Main.qml` starts hidden: `main.cpp` applies `gfx::configureWindow` (pipeline cache) and `FrameMonitor::attach` (GPU timestamps) before showing it, because both must precede scene-graph initialisation. Changing the renderer needs a restart, which `RelaunchGuard` performs by self-`execv`. Every window must connect `sceneGraphError` (`GraphicsInfo::watch`).
- **Glass pipeline.** `qml/components/BackdropBlur.qml` blurs the backdrop once (Kawase/Gaussian chain, parameters from `theme::blurPlan`); its `ShaderEffectSource` passes must stay *visible* (zero-sized), or Qt never updates them. `GlassPanel` samples the result via `Window.window.backdropTexture` (`resources/shaders/glass.vert` maps `qt_Matrix` back to window UVs + `glass.frag` / `liquid.frag`). With the Liquid Glass style every panel uses it (`GlassPanel.liquid`, default true); list rows must never be GlassPanels. Keep content inside `max(margin, panel.cornerInset)`. Effects limits (quality, style cap, backdrop animation, frame cap) come from `gfx::resolveEffects` + `QualityGovernor` (both pure), applied by `ui::EffectsController` (QML `Performance`). Artwork accents and the pre-blurred cover backdrop come from `theme::AccentEngine` (QML `Artwork`, `image://artwork`).
- **Network (`net/`, see `docs/network.md`).** All HTTP goes through `net::INetworkTransport` (`CurlTransport`: libcurl multi on the `NetworkService` thread; `send()` is thread-safe, callbacks run on the context object's thread via `CallbackChannel`). Never let curl resolve names: every host, IPv4 literals included, is resolved by `DnsResolver` and pinned with `CURLOPT_RESOLVE`; a resolver-start guard fails the transfer otherwise and tests assert `unexpectedCurlResolves() == 0`. Redirects are followed by the transport, not curl. Behind remote-resolving proxies (HTTP/HTTPS/socks4a/socks5h) destination names must not be resolved locally. Strict DNS (custom/DoH without fallback) must never reach `ISystemResolver`. Everything on the network thread is created there (`NetworkCore`); async continuations look transfers up by id or hold `QPointer`, never raw pointers. Proxy credentials come only from `auth::ISecretStore`, never from settings; diagnostics are redacted at the source (`net/Redaction`, `ProxyServer::displayUrl`). `net` returns `ErrorCode`s; HTTP error statuses are responses, not errors.
- **Caches (`cache/`, see `docs/caching.md`).** `CacheService` owns the `noctara-cache` thread: `AudioCache` (disk tier, entries keyed by track id + transcoding, never URL; sidecar `meta.json` written before any audio byte; 64 KiB pieces with XXH3 checksums; one fetch per entry), `MemoryTier` (thread-safe RAM tier), `ImageCache` (`image://cover/…`), `CachingTransport` (RFC 9111 HTTP cache wrapping the network transport; the API client must use `CacheService::transport()`). DRM tracks (`TrackInfo::drm`, encrypted HLS) are refused with `NotCacheable` before anything is created. `AudioReader`s are bound to a file generation (tagging rewrites the file). Cache tests use `tests/mock/FakeOrigin.hpp`; tagging fixtures are in `tests/fixtures/audio/`. Results returning `std::expected` must not be `(void)`-discarded (clang-tidy `bugprone-unused-return-value`): log the error instead.
- **Saved lists (`api/Snapshot`, see `docs/caching.md`).** `SnapshotStore` keeps the account's likes, library and opened playlists under `<cache>/library/<account>/` in api-v2's own JSON shape (read back by `parse::snapshot`; simdjson stays in `Parse.cpp`). `CollectionModel::setSyncedSource` shows the snapshot, fetches every page (200 at a time) and applies the fresh list with `applyEntries` (row-level diff: never reset unless items moved). Tracks read back are `stale`: the controller looks them up again before they play or are prepared. The catalog uses the store's remembered account until `/me` confirms it; a different account deletes the old lists. A queue started from a list follows it (`PlaybackController::follow`, `PlaybackQueue::addUpcoming`).
- **SoundCloud API (`api/`, `models/`, see `docs/api.md`).** `ApiService` owns the `noctara-api` thread with `ClientIdProvider` and `ApiClient`; requests go through `CacheService::transport()`. Use `fetch(client, endpoints::x(...), context, done)`; JSON is parsed on the API thread (simdjson only inside `api/Parse.cpp`). The OAuth token and `client_id` are only ever sent to `isApiHost()` URLs. Everything site-specific about `client_id` discovery stays in `api/ClientId.cpp`. `models::CollectionModel` paginates via `next_href` and hydrates stub tracks via coalesced `lookupTracks`. API tests use `tests/mock/FakeApi.hpp`; the live check is `--no-skip -tc="real api*"`. Covers are shaped on the CPU: `image://cover/mask/<fraction>/<url>` (`CoverArt.qml`).
- **Auth and the session (`auth/`, `ui/AccountController`, see `docs/auth.md`).** The signed-in account is one OAuth token, held in memory by `api::Session` and persisted only through `auth::ISecretStore` (`SecretServiceStore`: keyring via an injectable `IKeyring`, else the AES-GCM `EncryptedFileSecretStore`, else memory; the UI warns for the last two) — never in the config file, and sent only to `isApiHost()` URLs. `ui::AccountController` (QML `Account`) is the single sign-in entry point for pasted tokens and consented `auth::BrowserCookieSource` imports: a candidate is checked with its own `/me` (`ApiRequest::candidateToken`, cache bypassed) and installed in `api::Session` only once accepted, so a bad token never disturbs a working session; every sign-in/out/expiry bumps a generation and stale async answers are dropped. Expiry comes from `api::Session::rejected` (a 401 on any request) or a 401 on the background `/me`. Chromium cookies: `v10` = `peanuts`, `v11` = Safe Storage password (Secret Service, else KWallet over D-Bus), DB version ≥ 24 prefixes `SHA-256(host_key)`; see `docs/auth.md`. Wipe secret buffers with `auth::wipe` (it skips shared QByteArray buffers on purpose). A settings category with no generated schema rows (About, Accounts) is a **custom pane**: branch it in `qml/settings/SettingsView.qml`'s content Loader *and* special-case it in `SettingsController::categories()` so it shows in the sidebar.
- **Playback (`media/`, see `docs/playback.md`).** `PlaybackController` (QML `Player`) owns the queue (`PlaybackQueue`, pure) and talks to an `IPlaybackBackend`; `NativeBackend` opens each source in `AudioCache` and decodes it in a `Voice` thread (`StreamSource` → FFmpeg `Decoder` via a custom `AVIOContext` → `PcmRing`), and the `Mixer` runs in `QAudioSink`'s pull callback (gapless switch, crossfade, 15 ms ramps). FFmpeg must never open a URL: HLS is read as concatenated segments (init segment first), never through its HLS demuxer. Only `Mixer::replaceNext`/`setVoices` change what the audio thread reads; destroy a `Voice` only after that (see `NativeBackend::dropNext`). Stream URLs are resolved lazily through `StreamUrlResolver` (disabled in the controller's destructor because the cache calls it on its thread). The controller picks the backend per track (`backendFor`/`activate`): only the active backend's signals count; protected tracks go to `drm::DrmBackend`, are never prefetched, and are skipped as `ProtectedPlayback` when turned off. Covers for MPRIS/notifications are local files (`CoverFiles`), never URLs. Tests drive the backend with `FakeOutput` (pull at about real-time pace: the backend checks state every 100 ms) and the controller with `FakeClient`/`FakeBackend` (`tests/media_tests.cpp`); HLS fixtures are in `tests/fixtures/audio/hls-*`. Custom `QSGMaterial` vertex shaders need the batchable variant: the qsb rule passes `-b` for `.vert` files.
- **Protected playback (`drm/`, `electron/`, see `docs/drm-helper.md`, `docs/ipc.md`).** castlabs Electron (Widevine) plays protected tracks headless; Noctara never sees media, keys or licenses and must never get a way to save them. The IPC protocol is defined once in `electron/protocol.json`: `drm/Protocol.cpp` `#embed`s it, `electron/protocol.js` loads it, both validate every message; changing it bumps `version`. `DrmHost` owns the process (own process group, `PR_SET_PDEATHSIG`, heartbeat once ready, crash restarts, idle shutdown); `DrmBackend` resolves a fresh `api::ProtectedStream` per load and resumes after restarts. Network settings reach the helper through `drm::planNetwork` (startup switches + the `configure` message, which carries proxy credentials: never log `configure` or `load`). Pinned versions live once in `electron/helper-release.json`: `drm::HelperInstaller` sets the helper up by itself under `<data>/drm-helper/` (download through Noctara's transport with Range resume and SHA-256, libarchive unpack, app files `#embed`ded via `drm/HelperFiles.cpp`), and `xmake drm-helper` assembles `build/drm-helper` for development. Tests use the QtCore-only `noctara-mock-drm-helper` (`tests/mock-drm-helper/`, steered by `NOCTARA_MOCK_DRM_*` env vars); the real helper check is `--no-skip -tc="real drm*"`. Debug binaries linking the GUI stack start in ~12 s here (NVIDIA GL init under ASan), which is why the mock is separate.
- **Glass: blur and surface are separate.** `appearance.glass.style` = backdrop blur (kawase/gaussian/solid), `appearance.glass.surface` = frosted/liquid/flat (`Theme.glass.surface`, `Theme.glass.flat`). Liquid Glass needs a blur and falls back to frosted; flat panels have no lift, sheen, rim light or shadow. Never reintroduce a combined "style".
- **User themes (`theme/UserTheme`, `theme/ThemeLibrary`, see `docs/themes.md`).** Data only: parse, validate (unknown token/invalid value → issue + skip; syntax error → reject), then `Theme::setUserTheme` applies overrides after palette generation and re-enforces contrast when the setting is on. Theme files never reference paths or code. The examples in `docs/themes/` are parsed by a test; keep them issue-free.
- **Pages and navigation (QML).** `Main.qml` owns the page, the detail stack (`openPlaylist`/`openUser`/`openTrack`/`goBack`; the detail Loader *reuses* a page when one detail replaces another of the same kind, so pages react to `onDetailChanged`), the full-screen player and the context menus (`show*Menu` functions; components call them through `Window.window`; `trackActions()` holds the entries shared by every track menu). `ContextMenu` scrolls when taller than the window; `showAt(actions, windowPoint)` opens a follow-up menu (the playlist list) where the first one was. Detail objects come from `Catalog.playlist/user/track(id)`, kept 12 per kind. Lists go through `CollectionView` (rows `CatalogRow`, cards `Card`); new list roles must be required properties there. A view whose header fills in later (detail pages) stays at its start while the header grows: copy the `atStart`/`headerExtent` handlers of `CollectionView` into any other ListView with a header. Form dialogs put their controls as `Dialog` children (`confirmEnabled`, `initialFocus`). Shortcuts bind to `Shortcuts.sequences[action]`; add an action as a `keyboard.shortcuts.<action>` schema entry plus an `ActionShortcut` in `Main.qml`. Layout settings are read through `Layout` (typed), never `SettingsUi.value`.
- **Writes to the account** (`endpoints::write`: likes, playlist tracks, new playlists) are `Auth::Required` and bypass the HTTP cache (a successful write drops the cached GET of the same URL). SoundCloud replaces a playlist's tracks as a whole, so `Catalog::addToPlaylist` reads it with `playlistForEdit` (revalidated), appends, writes the whole list back, and serialises changes per playlist. Likes are optimistic (`isLiked` + `likedRevision` for bindings; put back with a `notice` on failure). The write shapes follow the web client and are only tested against `FakeApi`.
- **QML cost traps (measured).** A `Repeater` whose model is an array built from changing values (colours, a row's numbers) destroys and recreates every delegate on each change: use fixed inline-component instances (`PaletteDots`, `CatalogRow`'s `Stat`). A `Behavior on color` bound to `Theme.colors.accent` restarts on every crossfade frame: animate a scalar and compose the colour (`ButtonSurface` halo). Tooltips in repeated items use `LazyTooltip`.
- **Nested shapes follow the corner setting.** A shape inset in a rounded container is concentric with it: `min(height / 2, max(0, outerRadius - inset))`; a popup whose rows may round to pills pads by at least `(outerRadius - rowHeight / 2) * (1 - Math.SQRT1_2)` (see `ContextMenu`, `ComboBox`). Never give an inner highlight its own fixed token.
- **Cross-thread hand-offs** go through `core/Handoff.hpp` (`handoff::post`, `handoff::runAndWait`, or `send` + `barrier` for queued signals). In TSan builds it makes Qt's event-queue ordering visible (the distro Qt is uninstrumented); elsewhere it is a plain queued call. Use a `std::promise`, not `Qt::BlockingQueuedConnection`, to wait for another thread.
- **Appearance UX rules from user review:** colour presets (Auto / Midnight / Frost tiles) change colours only and are the sole control for the config-only `appearance.theme.mode`; "Midnight" and "Frost" are never translated. Every button-like control uses the *Button material* (`Theme.glass.buttons`) except primary actions and the flat nav rail. Grain lives in the backdrop only, never over text.
- **Do not run `clang-tidy -fix`** over several files at once: in this setup it applied replacements at shifted offsets (wrong `const`, renamed types, merged `if`s with init-statements). Fix lint findings by hand.
- **Selection indicators** (nav-rail pill, segmented-control pill) compute their geometry from the model and the control size. Do not drive them with `Binding` elements or toggle a `Behavior`'s `enabled` mid-animation: both left pills stranded after window resizes. Animate a separate offset instead (see `NavRail.qml`).
- **Software path.** Shader effects do not exist under the software renderer. Anything that uses `ShaderEffect` must sit behind `Graphics.hardware`; see `qml/components/Shadow.qml`, which uses our own SDF shader `resources/shaders/shadow.frag`. Do not use Qt 6.12's `RectangularShadow`: it leaks about 2 KB per destroyed instance.
- **i18n.** No user-visible string may be hardcoded. `lupdate` pre-fills a new message from an identical source in another context but leaves it `unfinished`: reuse the wording already established there. `noctara_en.ts` only carries the plural (`%n`) forms. In C++, use `tr` or `QCoreApplication::translate("Context", "literal")` with a literal so lupdate can extract it. In QML use `qsTr`. Schema labels use `QT_TRANSLATE_NOOP("Settings", …)`. Lower layers return `ErrorCode` values, and `i18n/ErrorMessages` maps them to translated text. Never chain `.arg(a).arg(b)` when a substituted value can contain `%1` (paths, URLs, server text): it gets replaced again. Use the multi-argument `arg(a, b)`. Changing the language applies live through `QQmlEngine::retranslate()`.
- **Objects returned to QML** from a `Q_INVOKABLE` must get `QQmlEngine::setObjectOwnership(..., CppOwnership)`. Otherwise the JavaScript GC deletes them; ASan caught exactly that in `SettingsController::page/subset`.

## Build-system specifics (`xmake/`)

- **Custom rules** (`xmake/rules/resources.lua`):
  - `noctara.qsb`: GLSL `.vert`/`.frag` to `.qsb`, embedded at `:/shaders/<file>.qsb`. Any qsb diagnostic fails the build.
  - `noctara.lrelease`: `.ts` to `.qm`, embedded at `:/i18n/`.
  - `noctara.qrcgen`: generates `.qrc` files from globs (QML, fonts, icons, data).
  - `noctara.moc`: replaces the stock moc for project headers and tracks the header's transitive project includes. The stock rule left stale meta-object code behind, which caused an ODR crash.
  - `noctara.qtfix`: strips stray `libQt5*` and `libQt6Bundled*` static libraries that xmake's Qt rule wrongly links.
- **Rule overrides.** Per-file rules use `{rules = {..., override = true}}` so the stock `qt.ts` and `qt.moc` rules do not process the same files twice. A no-op build compiles nothing.
- **Strict warnings** apply only to project sources, through per-file `cxxflags`, so moc and rcc output is unaffected. Third-party headers are suppressed locally with a comment, for example `tests/Doctest.hpp` and the designated-initializer pragma in `BuiltinSchema.cpp`.
- **toml++** is used header-only through `settings/TomlInclude.hpp` with exceptions disabled. Always include it via that header.
- **Sanitizer suppressions.** LSan suppressions (`core/LsanSuppressions.hpp`) cover only third-party GPU-driver and system libraries. TSan uses `tools/tsan.supp` (Qt/GLib/libdbus internals only); `test-tsan` runs every suite in its own process and excludes `settings.file`, `ui.settings`, `ui.presets`, `ui.icons` and `cache.service`, where TSan's thread registry aborts on thread-ID reuse after many `QThread` start/stop cycles. The suites whose cases create worker pools or service threads (the `perCase` table in `xmake/tasks/tasks.lua`) run one case per process; a case that still hits the registry abort is printed as skipped by name, and any data race fails. A registry abort counts as a failure in a whole-suite run, so a new suite that starts threads may have to go into `perCase`. Only reports lying entirely inside uninstrumented libraries (Qt incl. QtDBus, GLib, libdbus) are suppressed; never suppress one with a project frame.
- **System libraries** come through pkg-config packages (`pkgconfig::libcurl`, `libproxy-1.0`, `libsecret-1`, `taglib`, `libxxhash`, `simdjson`, `openssl` (auth, tests), `sqlite3` (auth), `libavformat`/`libavcodec`/`libavutil`/`libswresample` (media)). Qt Multimedia provides the audio device. The `net` target fails at configure time if libcurl lacks SSL, HTTP2 or IPv6. Include GLib-based headers (libproxy, libsecret) only from `.cpp` files.

## Tests

- `tests/mock/MockServers.*` provides local HTTP/HTTPS (generated self-signed cert, usable as a CA bundle), DNS (UDP+TCP, optional truncation), DoH, HTTP/CONNECT proxy and SOCKS4/5/5h servers with optional auth, each recording what it saw. `net_integration_tests.cpp` uses a `FakeSystemResolver` that counts calls and returns a poisoned address.
- Assertion messages may be evaluated even when the check passes (`-s`): use `test::describe(result)` and `test::errorOf(result)` from `TestUtil.hpp` instead of calling `.error()` on a result directly.
- Qt-dependent tests run under one offscreen `QGuiApplication` (`tests/main.cpp`, which also ignores SIGPIPE); wait for asynchronous results with `test::waitUntil`. Do not poll for an exact count or within a short window to catch an intermediate state: under ASan and load such tests flake. Hold the state with the fakes' hooks instead (e.g. `FakeOrigin::pauseAfter` / `failAfter`). QML components can be tested by loading them from `NOCTARA_SOURCE_DIR` with a stub singleton (see `IconHarness` and `WindowHarness`/`installStubs` in `ui_tests.cpp`); a singleton member the QML reads must exist in the stub (`kThemeStub`, `kPlayerStub`) or the harness logs errors. The pointer position carries over between tests: move it away (`QTest::mouseMove`) before checking hover-sensitive popups.

## Docs

`docs/` holds the architecture, design (tokens, materials, palette rules), themes (user theme format and examples), GPU and fallbacks, network (transport decision, DNS/proxy behaviour), caching (layout, tiers, tagging, DRM policy), playback (pipeline, queue, desktop integration, waveform), localization, performance, plan, and the generated configuration reference. `README.md` lists the dependencies and tasks.
